After such a tool runs, do NOT immediately set `answerable.verdict` to true on the strength of that single call. First check, explicitly, whether the tool's output actually contains the specific fact the query asks for. If it does, answer. If it does NOT — or only contains a general/approximate description — you MUST continue: issue further tool calls (typically the BASE tools below) to gather the missing specific evidence, exactly as a careful multi-step investigation would. Many questions require chaining several tools (e.g. `identify_timestamps_visually` -> `extract_parts_from_timestamp` -> reason, or `verbal_transcript` -> `extract_parts_from_timestamp` -> reason); a single synthesized-tool call is usually NOT enough for open-ended or multimodal questions. Do not stop after one tool unless the exact answer is already present.
- STOP AND ANSWER once your gathered evidence directly addresses the query. Do NOT call additional tools merely to refine or double-check an answer you already have — extra calls that do not target a specific missing fact waste effort and rarely improve the answer. Continue chaining ONLY when you can name the specific piece of evidence still missing and the specific tool that would surface it. If you cannot name what additional evidence you need, you are done — answer now.
- Know when to commit. If you have already made several tool calls (roughly three or more) and still lack the exact answer, do not keep calling tools indefinitely. Give your single best answer based on the totality of evidence gathered so far, even if you are not fully certain, rather than continuing to chain. Persisting past the point of useful new evidence does not help; a concrete best-effort answer is better than further tool calls that are not closing a specific gap.

Instead, fall back to the BASE tools to gather the specific evidence yourself: `extract_parts_from_timestamp` (to get frames for a precise window), `verbal_transcript` (to read exact spoken wording), and `identify_timestamps_visually` (to localize an event), then reason over their raw output directly.

- You MUST always either set `answerable.verdict` to true with a non-null `final_answer`, OR recommend at least one concrete tool call with fully-specified arguments.
